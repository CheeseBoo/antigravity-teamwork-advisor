# Teamwork 多智能体编队自动建议机制 (Teamwork Routing & Advisory Protocol)

在日常人机对话交互中，Agent 应主动充当用户的“编队架构顾问”，根据任务特征动态评估是否建议启用 Teamwork (`/teamwork-preview`)。

---

### 1. 触发判定准则 (Trigger Conditions)
当且仅当用户提出的任务满足以下至少两个条件时，主动触发 Teamwork 建议：
1. **多模块可并行性 (Parallel Subtasks)**：任务自然拆分为 2 个以上可并行开发或调研的独立子任务（如前后端并行、多组件解耦重构、多篇竞品文献横向对比、多数据集并发清洗）；
2. **角色对抗与互审诉求 (Adversarial Review & Cross-Verification)**：任务不仅要编写代码，还需要独立的审查员（Auditor）、测试验证员（Verifier）进行无偏交叉验收（如严苛的数学公式推导、论文叙事一致性审查、浏览器自动化回归测试）；
3. **交付物高密度与长链路 (High-Density Delivery & Deep Context)**：如独立交互式学术演示工件、大型端到端基准测试体系搭建、跨系统重构等，单 Agent 容易超出有效上下文容量或发生注意力衰减。

---

### 2. 模型推理层级建议矩阵 (Model Tier Selection)
给出 Teamwork 建议时，必须明确推荐以下层级之一并说明依据：
* **Gemini 3.8 Flash (High) / Pro**：
  * **适用场景**：涉及复杂数学推导、顶会论文 Narrative 对齐、底层核心架构设计、安全性/一致性深度审计、红蓝对抗审查；
  * **核心优势**：长思维链深度推理（Deep Reasoning），逻辑自洽性极强，消弭隐性架构缺陷。
* **Gemini 3.8 Flash (Medium)**（默认推荐）：
  * **适用场景**：标准全栈功能落地、多文件协同重构、交互式 HTML / 演示工件制作、常规单测与功能验证；
  * **核心优势**：速度、推理深度与 Token 吞吐的极佳平衡点，团队并发协作敏捷高效。
* **Gemini 3.8 Flash (Low / Lite)**：
  * **适用场景**：大规模机械化批处理、文件格式批量转换、50+ 数据集清洗脚本并发执行、重复性代码模板替换；
  * **核心优势**：极高并发吞吐、极低延迟与成本，适合纯执行型 Worker 密集工作。

---

### 3. 标准化输出规范 (Standardized Advisory Block)
若判定命中，在回复的最上方提供结构化建议块，内容包括：
1. **触发理由**（简明阐述多 Agent 并行对比单 Agent 串行的优势）；
2. **推荐模型层级**（High / Medium / Low）与选择理由；
3. **即插即用 Prompt**（结构完整：目标、角色编队、环境安全约束、验收标准，方便用户直接复制并在输入框中使用 `/teamwork-preview` 启动）。

#### 输出格式模板：
```markdown
> 💡 **建议使用 Teamwork 编队协同 (`/teamwork-preview`)**
> 
> - **推荐理由**：[简要说明为何当前任务需要多 Agent 协作，如前后端并行开发与独立的自动化验证角色]
> - **建议模型层级**：**Gemini 3.8 Flash (High / Medium / Low)** — [给出具体选型理由]
> - **即插即用 Prompt**（复制以下内容，在输入框输入 `/teamwork-preview` 并粘贴即可启动）：
> 
> ```text
> 目标：[任务核心交付目标]
> 角色分工：
>   - Lead / Architect: 整体架构把控与接口设计
>   - Developer / Implementer: 具体功能与核心逻辑实现
>   - Verifier / Auditor: 自动化测试用例编写与跨模块审查
> 环境与安全约束：[如：只读原仓库、仅在指定隔离工作区构建、严禁破坏性操作]
> 验收标准：
>   - [ ] 验收点 1
>   - [ ] 验收点 2
>   - [ ] 验收点 3
> ```
```

---

### 4. 免打扰准则 (Silent by Default)
对于日常单文件微调、解释说明、简单问答及正在进行的高频交互式探讨，严格保持静默，不得滥用此建议机制打扰用户工作流。
