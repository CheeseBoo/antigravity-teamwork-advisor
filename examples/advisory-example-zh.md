# 实际触发交互案例 (Real-World Interaction Example - Chinese)

本示例展示当用户在日常对话中提出一个复合型、长链路、具备多角色验证诉求的高难度工程任务时，Agent 如何依照协议自动评估并输出结构化建议。

---

### 用户输入 (User Prompt):
> “我想做一个企业级轻量化 RAG 知识库检索增强系统（RAG-Studio）。需要实现 BM25 + Dense 向量混合重排检索算法引擎，配套一个响应式的前端看板展示检索召回率指标，并要求提供一套基于无头浏览器的自动化端到端测试，确保全流程无 JS 报错。”

---

### Agent 输出响应 (Agent Response):

> 💡 **建议使用 Teamwork 编队协同 (`/teamwork-preview`)**
> 
> - **推荐理由**：该任务自然包含**核心混合检索算法引擎**、**响应式前端工作台**与**浏览器自动化端到端测试**三大可解耦模块，且要求严格的“编写 $\leftrightarrow$ 审查”红蓝对抗无错校验。单 Agent 容易在上下文超长时发生注意力衰减，多 Agent 并行编队可实现“分工构建与实时互审”。
> - **建议模型层级**：**Gemini 3.8 Flash (High)** — 任务涉及复杂向量索引构建、混合重排算法与跨端状态同步逻辑，需要高推理深度以确保架构零隐患。
> - **即插即用 Prompt**（复制以下内容，在输入框中输入 `/teamwork-preview` 并粘贴即可启动）：
> 
> ```text
> 目标：构建企业级轻量化 RAG 检索增强平台（含混合检索引擎、响应式看板与自动化测试套件）。
> 角色分工：
>   - Backend Architect: 负责向量索引、BM25 混合重排算法引擎与检索 API 实现
>   - Frontend Engineer: 负责响应式前端可视化工作台与实时交互看板
>   - QA Verifier: 编写并执行自动化端到端测试脚本，验证检索指标与全流程 UI 交互
> 环境安全约束：
>   - 严格在指定输出目录下生成静态产物，严禁破坏性操作
> 验收标准：
>   - [ ] 后端混合检索链路通过基准检索与单测
>   - [ ] 前端看板秒级加载并实时呈现指标变化
>   - [ ] 自动化测试脚本验证 0 报错且全链路测试通过
> ```
